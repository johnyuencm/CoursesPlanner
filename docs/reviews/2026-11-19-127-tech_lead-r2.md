## Checks

1. **Moved crawl-status code.** `readState` is now private in catalog-service/roadmaps.ts:37-59. It is the old body with one change: status-file errors get the file path as a prefix. Order is kept (status, then programs, then the "missing directory" check). Validation is kept. Callers:
   - `crawlRoadmaps` (roadmaps.ts:132): same behavior. The throw is not caught there, so the path goes only to the CLI error. It is not persisted into a status `reason`.
   - `readCrawlDirectory` (roadmaps.ts:63-69): used by cli.ts:52,56 and server.ts:96,99.
   - grep finds no other importer of `readState` or of the removed re-export of `readProgramDirectory` from catalog-service/roadmaps.ts. tests/packaged-snapshot.test.ts imports `readProgramDirectory` from lib, which still exports it.
   - No app or Worker path needs the status. On the Worker, `snapshotAsset` never held the status file, so the old `readState` always took the "no persisted status" branch. The new `readProgramDirectory` (lib/roadmap-reader.ts:94-104) computes the same value: `summarize(programs, latestUpdate(programs))` or `initialStatus`. Worker bodies do not change.
   - `latestUpdate` with no `also` equals the old `updatedAt` expression. With `also`, it equals the old expression with a persisted status.
2. **Log line** (app/api/roadmaps/route.ts:36-37).
   - Error path only. It runs after the three known prefixes, so 404 and "not ready" 503 do not log.
   - The body stays the fixed text. tests/roadmaps-route.test.ts:229-241 asserts the body has no `ENOENT` or `universities.json`, and that one log line names the file.
   - Content: a file path and an error from file read, JSON parse or schema validation. No secret source is on this path. Request ids pass `SAFE_ID` before any read, so no request input reaches the log. No log injection.
   - The catalog service keeps its generic 5xx body (server.ts:42-44). The new path prefix does not reach a response.
3. **Worker CPU.** Per uncached request: one `programs.json` validate and sort, plus `summarize`. This is the same work as the old Worker path, minus a status-asset lookup. The 200-body memo is unchanged. A 503 is not memoized, so a broken deploy logs one line per request. That is a `console.error` call only. No new cost on Workers Free.
4. **Tests.**
   - tests/snapshot-manifest.test.ts:66-80 pins the 404 for "status ready, no programs.json" (round 1 low finding 1).
   - tests/snapshot-manifest.test.ts:82-111 compares list, `?university=` and each published `&program=` body and status, clean copy against a copy with `{version:1}` as the status file. It also compares CLI `--roadmap` output. At a5e2ad7, `readProgramDirectory` called `readState`, which throws on `{version:1}`. So the list and `?university=` cases are red on a5e2ad7 and green now. Not a false green (round 1 low finding 2).
   - tests/snapshot-manifest.test.ts:113-121 pins that the operator views still read the status and name the file in the error.
   - NODE_ENV is not `production` in tests, so the memo cannot hide a regression.
   - I ran `npx tsx --test` on snapshot-manifest, roadmaps-route, roadmaps and packaged-snapshot tests: 31 pass, 0 fail. `tsc --noEmit`: exit 0.
