## Findings

### M1 (medium): a re-crawl drops `shortName` from Map-tier roadmaps

- `catalog-service/roadmaps.ts:212-222` builds a new `ProgramRoadmap` object and writes it with `atomicWrite`. It does not read the old file. The hand-added `shortName` is lost.
- When: a rediscovery (no `programs.json`, so all programs go to `queued`) or a manual reset to `queued`/`unverified`. A normal `--crawl-roadmaps` run skips `ready` programs (`roadmaps.ts:191`), so the trap is not on every run.
- The source of truth for `shortName` is a file that the crawler owns. That is the architecture problem. `data/catalog.json` does not have this problem: `refresh.ts:296` copies it from the source definition, and `tests/catalog-service.test.ts:549` pins it.
- Guards that exist: `git diff` shows the removed line, and `tests/sitemap-metadata.test.ts` fails ("no short name in the catalog of ..."). `docs/add-courseleaf-college.md` step 5 tells the operator to add it again.
- Why not high: no production data is lost, git can restore the value, and CI catches it. But `npm run deploy` deploys `dist/` and does not run the tests, so a local re-crawl, build and deploy can ship M2.

### M2 (medium): with no `shortName`, `pageTitle` gives worse titles than before the PR

- `lib/program-page.ts` `shortName()` falls back to `programName()`. `pageTitle()` computes `TITLE_MAX - (3 + name.length)` and does not check the result.
- Measured with the fallback names:

| Fallback name (length) | Room | Course title |
| --- | --- | --- |
| `Northeastern Computer Science, MSCS (Boston)` (44) | 13 | `CS 5010… · Northeastern Computer Science, MSCS (Boston)` |
| `Northeastern University Computer Science, MSCS—Seattle` (54) | 3 | `CS… · Northeastern University ...` (every course title is the same) |
| a 73-character name | -16 | `CS 5010 Programmin… · ...` (`slice(0, -17)`, cut inside a word, over 60) |

- Before the PR, a long name gave long but unique titles. Now the fallback gives duplicate or empty course titles on hundreds of pages. This is an SEO regression on the exact path that M1 opens.
- `clip(text, max)` has no guard for `max <= 1`. `lastIndexOf(" ", max - 1)` with a negative index and `slice(0, max - 1)` with a negative end give wrong output.
- No validator limits the length of `shortName`. A future college with a long `shortName` hits the same path.
- The sitemap test catches all of these for published programs (uniqueness and 90% rule). Thus the risk is a deploy without tests, as in M1.

### L1 (low): validators do not agree on a blank `shortName`

- `lib/catalog.ts:204` accepts `"  "` for `Catalog.shortName` (`length === 0` check only).
- `lib/catalog.ts:392` and `catalog-service/registry.ts:28` reject it (`trim()`).
- The effect is small: a blank value gives a title that ends in ` · `.

### L2 (low): `shortName` is optional everywhere, and only a test makes it required

- A published program without `shortName` passes `validateProgramRoadmap` and the snapshot build (`lib/snapshot-manifest.ts`). Only `tests/sitemap-metadata.test.ts` fails.
- For a future college this failure mode is clear (the message names the path). It is acceptable if CI stays the gate. A build-time check for published keys would make M1 and M2 fail closed.
- No check makes `shortName` unique across programs. Two programs with the same value and a shared course code give the same title. The uniqueness test catches this for shipped data.

### L3 (low): the length test is looser than the result

- `tests/sitemap-metadata.test.ts` asserts 90% of titles at 60 characters or less. The PR measures 357 of 357. A regression from 100% to 91% passes.
- This matches the issue acceptance criterion. It is not a false green.

### L4 (low): `clip` edge cases

- Lengths use UTF-16 code units. The hard cut (`slice(0, max - 1)`) can split a surrogate pair. All 433 current titles are in the BMP (only `’` is non-ASCII), so there is no current effect.
- The joining-word list is case-insensitive, so a real trailing word such as "A" or "In" goes too (`"Calculus Part A Extra"` at 16 gives `"Calculus Part…"`). This is cosmetic.
- An open bracket or quote before the cut stays (`"Data (…"`). No current title has this.
- "…" counts as 1 character toward 60. Correct: the test measures the full string.

## Checked and correct

- `clip`: the result is never longer than `max` for `max >= 2`. Word path: `end <= max - 1`, plus 1 for "…". Hard path: `max - 1` plus 1. All 433 course titles fit in 60, and all are unique with the real short names. The 2 clips that end in a number (`ARTG 5100 Information Design Studio 1…`) are correct.
- Title merge: the program layout template `%s · <short name>` replaces the root template for child pages. The test merges root, program layout, Explore layout and page with `vinext/shims/metadata` `mergeMetadata`, which is the shipped merge. This is a real test, not a mock.
- Description: `unlockCount` uses the same `transitiveUnlocks` call that `unlockSummary` used. `clip(..., 160)` bounds it. The test asserts every course page.
- Header CSS: the sidebar hides `.brand-name` and `.brand-program` at `max-width: 1180px`. Thus 1180 px is the correct breakpoint, and the 860 px in the issue understated the gap. At 861-1180 px, `.topbar` is a grid and `.topbar-program` spans `1 / -1` as a new row. The sticky panels that use `top: 80px` (`.audit-panel`, `.page-rail`) are `position: static` at 1180 px or less, so the taller topbar breaks no offset. At 860 px or less, the flex order is program line, utilities, then search (`order: 3`). The topbar is about 20 px taller on phones. That is acceptable.
- Worker CPU (#110, #87): program pages use `generateStaticParams` and are prerendered, so metadata runs at build time. If the Worker renders a page, the added cost is 1 regex and 1 string join. No new per-request cost.
- Intro on `/`: `tests/ia.test.ts` reads it from `renderToStaticMarkup` server HTML and limits it to 300 characters. The page is static.
- Refresh of the Seattle catalog: `registry.ts` validates `shortName`, `refresh.ts:296` copies it, and a test pins it.
- No test was skipped, deleted or loosened. `tests/ia.test.ts:147` changes an expected template to the new value. That is a correct update, not a loosened check.
- Security: no new trust boundary. `shortName` comes from committed JSON and React escapes it.
