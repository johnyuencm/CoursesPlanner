## Correctness

- Error messages did not change. Thus the CLI and the build
  (`lib/snapshot-manifest.ts:76`, wraps `error.message`) keep the same text.
  `tests/snapshot-manifest.test.ts:52` still matches `Unknown roadmap program`.
- `RoadmapReadError` extends `Error`. Callers that only read `.message` still work.
- The `kind` type is `keyof typeof ROADMAP_READ_ERRORS`. A new kind without a
  map entry fails typecheck. This is a sound single source of truth.
- `missing-programs` is thrown only when the university is crawlable
  (`lib/roadmap-reader.ts:142`). A non-crawlable university has no
  `programs.json` by design. It still gives `unknown-program` 404. This is correct.
- When `programs.json` is missing, an unknown program id also gives
  `missing-programs`. This is correct: without the file the reader cannot know
  if the id exists.
- `instanceof` is safe here. `catalog-service/roadmaps.ts:25` re-exports from
  `lib/roadmap-reader`, so there is one class instance per process.

## Findings

### Low 1: `missing-programs` maps to 404

`lib/roadmap-reader.ts:24`. A missing data file is a server state, not a
missing client resource. 503 is the more exact status. The old #127 test also
asserted 404, and the issue does not set a status. The body text is true. I do
not block on this. If `project_manager` asks for 503, I agree.

### Low 2: `invalid-programs` kind skipped

The issue names `invalid-programs` as an example kind. An invalid
`programs.json` throws a plain `Error` from `readPrograms`
(`lib/roadmap-reader.ts:94-99`). The route answers 503 "Roadmap data is
temporarily unavailable." and logs the cause. The text is true and generic.
The acceptance list does not require this kind. Acceptable as a skip, but it
must be named in the PR body.

### Low 3: selector still says "Queued ... waiting for crawl" without `programs.json`

`readProgramDirectory` (`lib/roadmap-reader.ts:109-119`) returns
`initialStatus` ("queued") when the file is missing. In dev, the selector then
shows a false state. This is a different path and is outside the acceptance
list. File a follow-up issue so the skip stays visible.

## ack

Findings are low only. The red check proves the tests fail without the fix.
