## Checks

1. **Other build-time reads of ignored files.** I traced `vite.config.ts` (`programPageIndex`, `buildSnapshotAssets`), `lib/snapshot-manifest.ts`, `lib/program-catalog.ts:53-70` and `lib/catalog.ts`. Each reads only a tracked path. `.gitignore:11-21` ignores `data/catalogs/**` except `programs.json`, the five roadmaps and the reports. No directory listing (`readdir`) is on the build path, so `raw/` and `zz-extra.json` cannot leak in. Result: no other read.
2. **503 to 404 change.** Old: `readReadyRoadmap` → `readState` threw "Completed discovery is missing its program directory" → 503 "temporarily unavailable". New: `readPrograms` gives undefined → "Unknown roadmap program" → 404 (app/api/roadmaps/route.ts:34, catalog-service/server.ts:103).
   - The client (components/roadmap-selector.tsx:233-238) checks only `response.ok` and shows the error text. It has no retry on 503. No client depends on 503.
   - Errors are `no-store` and are not put in the memo (route.ts:25-29, 87-89). A 404 cannot stick.
   - The deployed Worker ships `programs.json` in `_snapshots/manifest.json`, so this state cannot occur in production. It needs a local repo with a status file and no `programs.json`.
   - The "not ready" signal (`Roadmap is not ready:` → 503) is unchanged and still tested (tests/roadmaps-route.test.ts:192-203).
   - Also new: an invalid or mismatched status file no longer breaks a roadmap read (it was 503 before). This is the goal of the ticket.
3. **Worker CPU.** Per request, the old path did: status asset lookup (not in the manifest, so cheap undefined), `programs.json` validate and sort, `summarize`. The new path drops the status lookup and `summarize`. The work per request goes down, never up. The 200-body memo (route.ts:39-43) is unchanged.
4. **Tests.**
   - tests/snapshot-manifest.test.ts:58-64 compares the full asset `Map` of a clean copy and a dirty copy with `deepEqual`. On base 04e51ff, `readReadyRoadmap` called `readProgramDirectory` → `validateRoadmapCrawlStatus({version:1})`, which throws. So the test is red on base and green on head. It is not a false green.
   - `plantCrawlOutput()` is a pure move of the old inline setup (tests/published-programs.test.ts). Nothing was weakened.
   - I ran `npx tsx --test tests/snapshot-manifest.test.ts`: 7 pass, 0 fail.
5. **Architecture.** `readPrograms()` is a straight extract of the old validation block. `readState()` keeps its order: status first, then programs, and the "missing directory" check. Coupling goes down: the build no longer depends on crawler state. Validation is kept (no check was dropped).
6. **Security.** `universityDir()` still validates the id. `programId` is still checked by `validId` before the path join. No new trust boundary.
