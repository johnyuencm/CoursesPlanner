## `clip()` change

- The `i` flag is gone. Each word is listed in lower case and with a capital letter. Thus `IT`, `ITS`, `OR` and `IN` stay. The test `MISM 6200 Managing IT…` pins this.
- New items that are removed at the end of the clipped text: `.`, `It`/`it`, `Its`/`its`, `this`, `that`, `other`.
- `no` and `not` are not in the list, so a negation stays. I checked these examples:
  - `It unlocks no other course in` at 20 gives `It unlocks no…`.
  - `CS 5010 Not for credit in this program` at 22 gives `CS 5010 Not…`.
- A word at the start of the text has no space before it, so it does not match. Thus the text cannot become empty, except in the `max < 2` guard.
- Titles: I ran the old and the new regex over all 433 course titles of the 5 published catalogs with the real short names. 0 titles changed.
- Unicode: the regex has no `i` or `u` flag and uses only ASCII words. No case-folding problem is possible. The surrogate-pair note from round 1 (L4) is unchanged and has no current effect.
- Test: the description test now fails when a clipped course description ends in `It…` or `.…`. This checks the behavior on real sitemap data, not only on examples.

### R3-L1 (low): a period in an abbreviation goes too

- `Earn a Ph.D. degree in computing` at 20 gives `Earn a Ph.D. degree…`. A cut that lands right after `Ph.D.` gives `Ph.D…`.
- No current title or description has this. This is cosmetic.

### R3-L2 (low, from round 1): a cut just before `no` can mislead

- If the cut lands between `unlocks` and `no`, the description ends `It unlocks…`. A reader can think that the course unlocks other courses.
- This is not new in this round, because round 1 had the same cut. The new rule does not make it worse. Pin it only if a real description hits it.

## Header CSS and markup

- `.topbar-program` now has `white-space: nowrap`, `overflow: hidden` and `text-overflow: ellipsis`. `overflow: hidden` sets the automatic minimum size to 0 in the grid (861-1180 px) and in the flex row (`flex-basis: 100%`, 860 px or less). Thus a long name cannot widen the topbar or make the page scroll sideways.
- At 620 px or less, `.topbar-program-full` is `display: none` and `.topbar-program-short` is `display: inline`. Above 620 px, the short span is hidden. `display: none` also hides the other span from screen readers, so a screen reader reads only one name.
- The ellipsis applies to the inline content of the block `<p>`, which is correct for the 2 spans.
- `shortName` comes from `readProgram()` in the server layout. Thus it is in the first HTML, and there is no hydration mismatch. Without a short name, the fallback is the long `programName`, and the ellipsis clips it on one line.
- No other layout rule depends on the height of the topbar at these widths (round 1 check).
