Review at 9ec5041 (main session, Claude Opus 5.5). Verdict: merge.

- Root cause: the first program request in each isolate read and parsed the 150 KB catalog to build the page set, and every program request waited for it.
- Fix: the build writes `virtual:program-pages` (125 paths, 8.6 KB), and `worker.ts` builds a Set once at isolate start. A request does one Set lookup, with no I/O and no `await`. `isUnknownProgramPath` still checks `isProgramPath` first, so non-program paths are untouched.
- The index and the snapshot assets come from the same build, so they cannot disagree.
- A test pins the cheap path (no `readCatalog` or `await` in `worker.ts`). CI green.
- Live proof follows after the deploy (`docs/deploy.md`).
